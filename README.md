# Music Manager

Программная система для менеджера музыкальных групп.

Курсовой проект по дисциплине «Программирование на языках высокого уровня».
Институт информационных технологий БГУИР, специальность «Компьютерная инженерия».

## О чём проект

Приложение для учёта работы менеджера музыкальных групп:
ведение справочников, планирование концертов, учёт договоров,
построение отчётов за период. Разграничение прав по ролям
(администратор / менеджер).

Интерфейс — оконный (FLTK), данные хранятся в локальном файле SQLite.
Язык — C++20.

## Возможности

- **Аутентификация**: вход по логину и паролю, пароли хранятся в виде SHA-256 с солью.
- **Роли**: администратор и менеджер. Раздел «Пользователи» доступен только администратору.
- **Справочники**:
  - группы (название, жанр, описание, менеджер);
  - музыканты (ФИО, телефон, email, инструмент, группа);
  - площадки (название, адрес, вместимость, контакт).
- **Концерты**: группа, площадка, дата, гонорар, расходы, статус.
- **Договоры**: привязка к концерту (1:1), номер, дата, сумма, статус.
- **Отчёты**: сводка по концертам за период, разбивка по группам, список неоплаченных договоров.
- **Детали**: окно «Подробнее» для групп — состав музыкантов.

## Сборка

### Зависимости

Linux (Debian/Ubuntu):

```bash
sudo apt install build-essential cmake libfltk1.3-dev sqlite3
```

### Шаги

```bash
git clone <url>
cd mmanager
cmake -S . -B build
cmake --build build -j$(nproc)
./build/music_manager
```

Файл базы данных music.db создаётся автоматически при первом запуске
в текущей рабочей директории.

## Первый вход

При первом запуске автоматически создаётся администратор:

* Логин: `admin`

* Пароль: `admin`

Рекомендуется сменить пароль после первого входа (пока не реализовано —
в планах). Дальше администратор может создавать других пользователей
с ролью «менеджер».

## Модель данных

```bash
roles ← users
users ← bands
bands ← musicians
bands ← concerts ─→ venues
concerts ← contracts
```

* `roles` — роли (admin, manager);

* `users` — пользователи;

* `bands` — музыкальные группы;

* `musicians` — музыканты (привязаны к группе);

* `venues` — концертные площадки;

* `concerts` — концерты (группа + площадка + дата + суммы + статус);

* `contracts` — договоры (связь 1:1 с концертом).

Все внешние ключи включены (`PRAGMA foreign_keys = ON`), удаление
связанных записей невозможно без предварительной очистки.

## Безопасность

* Пароли хранятся как `SHA-256`(пароль + соль); соль — 16 случайных байт в hex.

* В открытом виде пароли не сохраняются нигде.

* Все SQL-запросы — через подготовленные выражения (`sqlite3_prepare_v2`), что исключает SQL-инъекции.

* Разграничение прав: раздел «Пользователи» — только для роли admin.

* Защита от самоудаления администратора.
